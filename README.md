# 雨天実験室

雨の中を走ると濡れにくい？ 一様分布と掃引面積から、固定した直方体人体と濡れの飽和までを試す、ブラウザ内で完結する実験サイト。

## 開発

Node.js 22系（22.12以上）、24系、または26以上とnpmを使用する。CIはNode.js 24を使用する。

```sh
npm ci
npm run dev
npm test
npm run typecheck
npm run build
npm run preview
npm run format:check
```

開発サーバーは `http://127.0.0.1:5173/`。`npm run format` で整形する。

## 構成

- `src/simulation/`: 点雨粒の生成、線分と直方体の衝突、濡れ格子、解析式、固定シードのテスト。UIから独立した計算。
- `src/components/`: SVGの掃引図、Three.jsの人体と雨、操作部品、Workerを用いた低速・高速比較。
- `src/App.tsx`: 段階的な実験記事と実験の実行管理。

企画は [project-overview.md](project-overview.md)、実装計画は [implementation-plan.md](implementation-plan.md) を参照。

## モデルと近似

導入では鉛直線分の後に、進行方向の後ろへ横線分を加えた逆さL字を試す。2次元の一様な点密度 n、高さ h、横線分の長さ d、移動距離 L、速度 v、雨の落下速度 w に対し、縦の掃引面積は hL、横は dwL/v。両領域の内部は重ならず、期待衝突数は n(hL + dwL/v)。これは3次元の降雨強度・被雨量とは区別する。直方体の導入では前提と正面・上面の被雨量の関係を説明し、寸法の数値表示と後段の操作に連動する被雨量数値は表示しない。

無風、一様な鉛直雨を仮定する。人体は6つの固定直方体（高さ1.8m）で、全体の前傾と水平回転のみを変える。粒子1点は0.25mLを代表し、濡れ跡の初期面積は20cm²。いずれも例示値で、実測値ではない。

雨の強度をm/sに変換し、落下速度と代表水量で割って点密度を求める。周辺の4×3×3mの領域に一様な点群を置き、上流の2面から相対速度に応じた流入を生成する。初期配置でも上流の人体に遮られる点を除き、影の中に雨を発生させない。生成数は期待値を不偏にランダム丸めし、流入時刻と位置を一様にサンプルする。Poisson過程そのものの再現ではない。

1/60秒の固定刻みで雨粒の移動線分を全パーツと交差判定し、最初の衝突だけを記録する。面ごとの約1.5cmの格子で円形濡れ跡の重なりを近似する。濡れ面積率には雨が届かない面も含まれ、全表面が100%になるとは限らない。各面が95%に到達した最初の時間を記録し、未到達は未到達とする。橙色の補助表示は、格子中心から雨の上流へ逆向きに線分を伸ばして遮蔽を検査した到達範囲の推定。比較グラフの面積率はこの到達範囲を分母にし、全表面の割合も別に表示する。

途中で条件を変えると濡れを保持する。雨の強さ・落下速度を変えた際は周辺の点群を新しい密度で再配置する。瞬間的な姿勢変更で掃引される水量は計算しない。距離を変更した際は現在位置から新しい目標まで進み、現在位置より短い距離を指定した場合は停止する。再実験で距離・時間・濡れをリセットする。

計算粒子は最大6000点、描画は最大1800点。計算の上限はエラー停止し、黙って雨量を減らさない。描画が重い場合は描画粒数と画素比のみを下げる。再生倍率は1・5・20・100・200倍から選択でき、初期値は20倍。倍率は1描画フレームあたりの固定刻み計算回数だけを増やし、物理条件や時間刻みを変えない。1フレームの計算予算は約12msとし、指定倍率に追いつけない場合は実験時間の進行を遅くして、固定刻みと雨量を保持する。タブが非表示になれば一時停止する。歩行1.5m/sと小走り3.0m/sの固定プリセット比較はWorkerで計算し、中止できる。比較セクションにも同じ条件スライダーを表示し、速度以外の条件を人体セクションと同期する。比較の速度操作は省略し、カニ走り角度は両セクションでおまけとして折りたたむ。短距離・長距離ボタンは共有距離も更新する。グラフの横軸は移動距離を初期表示とし、経過時間に切り替えられる。時間軸では各速度の到着時点で線を終える。条件変更後のグラフには変更前の結果であることを表示し、再計算は明示的なボタン操作で行う。

人体セクションでは実行中の結果を一時停止して最大3件記録できる。記録は条件、進行距離、時間、被雨量、全表面と部位別の濡れ面積率、途中の条件変更の有無を含む。条件変更やリセットで記録は変わらず、ページ再読み込みで消える。記録の設定から新しい実験を始められるが、途中変更の履歴を再生するものではない。

## 公開

静的出力は `dist/`。Viteの `base: './'` でGitHub Pagesのリポジトリ配下にも対応する。

GitHubリポジトリに接続し、Settings → PagesのSourceをGitHub Actionsに設定する。`main` へのpushで、整形・テスト・型検査を含むビルド成功後に公開する。PRでは検証のみ。公開操作はリポジトリ接続後に実施する。

公開手順は [Vite公式ドキュメント](https://vite.dev/guide/static-deploy.html#github-pages) と [GitHub公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) に沿う。
